# Cue audio tools

The audio cue detector (Balloon Boy's vent bang and the other extracted
references) and the Bluetooth A2DP capture it reads from the phone. The labels
are defined in [`../README.md`](../README.md). Reference samples come from the
game APK (`../dump/extract-samples.sh`) and are local evidence: never commit
them, or any capture.

| Tool | Kind | Purpose and interface |
|---|---|---|
| `tools/cue/capture-bt-audio.sh SECONDS [outdir] [bt-mac]` | external-device action | Captures the phone's fully rendered A2DP mix through the validated BlueALSA source PCM, including SoundPool cues the phone's internal playback capture cannot hear. `--check [bt-mac]` is a read-only preflight that prints `audio-route=READY` or `audio-route=UNKNOWN` and exits non-zero when the source PCM is absent. Use `--start OUT_BASENAME [bt-mac]` / `--stop OUT_BASENAME` for acceptance evidence: that path records negotiated format and host-clock bounds, then computes `missingFraction` and `timeAxis` (`CONTINUOUS` only at <=0.5% absolute duration error). Recording requires the phone connected as an A2DP source, temporarily gives `bluealsa-cli open` exclusive access when `bluealsa-aplay` is monitoring, restores monitoring on exit, and refuses to write game audio inside the repository. The host's regular/FNaF mode contract and three-run continuity gate are in `docs/device/ANDROID-AUDIO-CAPTURE.md`. |
| `tools/cue/fnaf4-cues.py --refs DIR --live PCM [--raw OUT] [--events OUT.jsonl] [--hearing MODEL] [--families LIST] [--no-breath] \| --wav REC --start-wall-ms MS` | detector | FNaF 4's cues out of the A2DP mix, live from BlueALSA or from a recording: matched filters at 11 kHz for each sample family (samples that are one recording under several handles are one family -- our carpet run and one of Foxy's moves are the same file), printed as onsets on the host wall clock, and the breathing loop's best NCC every 100 ms against every lag of the circular reference, with its loop phase. The A2DP path's own latency is not removed (measured 112-244 ms behind the helper's frames). Fredbear's families (fb-left, fb-right matched channel against channel; laugh) take a 1 s window, a low publishing floor and a hop cap from the hearing model (default `tools/device/models/hearing-fnaf4-fredbear-moto-g56-v204.json`): they sit ~5 dB under the room, and the runner accepts only candidates on the level's grid. On Night 5 the runner passes `--families run,fb-left,fb-right,laugh --no-breath`: the full set cost 109 ms of a 100 ms hop on a loaded host. |
| `tools/cue/test-fnaf4-cues.py` | check | No-sample gate for the Fredbear families: the hearing model names exactly the detector's families and handles (a mismatch is refused), a synthetic side sound 5 dB under noise is published at its onset by the model's window and not by the old 0.55/0.6 s one, and a 6.3 s laugh publishes within its hop cap. |
| `tools/cue/test-bt-audio-collector.py` | check | Gate for the collector: first/final PCM receipt bounds, byte accounting, and a terminal state written on SIGINT. |
| `tools/cue/bt-audio-collector.py --pcm PCM --raw OUT --state OUT.json ...` | recorder | Owns `bluealsa-cli open` for `capture-bt-audio.sh --start` and records the first and final PCM receipt times, so the loss figure measures the stream rather than process start-up and teardown. A SIGINT still writes a terminal state. Gate: `tools/cue/test-bt-audio-collector.py`. |
| `tools/cue/bt-audio-link.sh --ensure\|--status [--game-package PACKAGE] [bt-mac]` | external-device action | Brings the phone's A2DP link to this host up without a hand on the phone: turns the phone's Bluetooth on, connects the A2DP Source profile over D-Bus (`bluetoothctl connect` picks LE on this dual-mode phone and fails), and if BlueALSA still shows no PCM, opens the phone's Bluetooth settings, finds the host by name with `uiautomator dump` (swiping to `Saved devices`), taps it, and restores the named game package if Settings had to take focus. FNaF 2 remains the compatibility default; FNaF 1 passes `--game-package com.scottgames.fivenightsatfreddys` explicitly. Exits 0 only on `capture-bt-audio.sh --check` READY. Menu-only input; refuses to tap with the named game in front. `--tap-point NAME < ui.xml` is the parser alone. |
| `tools/cue/audio-authority.py [--socket PATH] [--model MODEL] [--profile PROFILE] [--raw-output PATH]` | external-device authority | Owns the live rendered-audio observation outside Android and publishes bounded `fact-message-v1` JSONL to stdout and/or a Unix socket. The current adapter reads BlueALSA A2DP; `source=audio-authority` is transport-neutral and `calibrationProfile` identifies the active receiver, so an ESP32 adapter can retain the controller contract with its own profile. `--raw-output` preserves the same authoritative PCM read with first-read timing metadata outside the repository. `--check` is a read-only BlueALSA route preflight; missing routes are `UNKNOWN`, never a negative cue. |
| `tools/cue/latency-experiment.py preflight|run|analyze` | report (`run` retired) | Analyses the retained paired visual/A2DP latency sessions: host/helper monotonic clock interpolation, p50/p95/max/jitter, losses, and the 750 ms temporal decision. `run` is retired (Companion 0.2.0, 2026-09-27): it bridged facts into the APK's audio-fact port and logged the `GET` single-pixel luma, and the Companion has neither any more; `analyze` still reads every retained session and `preflight` checks the phone and receiver route. |
| `tools/cue/collect-facts.py --socket PATH --output OUT` | external-device action | Subscribes to one already-running audio authority Unix stream and persists its bounded `fact-message-v1` JSONL without copying raw PCM. `trial.sh CUE_AUDIO=1` uses this to keep a per-run authority sidecar. |
| `tools/cue/test-audio-authority.py` | check | Phone-free regression for the external authority's fact bounds, transport-specific profile, PCM downmix, socket publisher, optional wind matcher, and BlueALSA route gate. |
| `tools/cue/test-capture-bt-audio.sh` | check | Phone-free mock regression for the A2DP route preflight: ready, disconnected, and malformed Bluetooth addresses are distinct outcomes, with no real audio or device. |
| `tools/cue/test-bt-audio-link.sh` | check | Phone-free check of `bt-audio-link.sh`'s uiautomator node -> tap-point parser on a fixture cut from the g56's Bluetooth settings: exact name only, prefix and absent names refuse, centre of the bounds. Runs in `npm run test:contracts`. |
| `tools/cue/features.py` | module | Stdlib front end for cue audio — decode, downmix to 16 kHz mono, 32 ms frames, 16 log-spaced bands with each frame's mean removed. Includes its own FFT; the repository's Python tooling has no numpy. |
| `tools/cue/reference-report.py [refdir]` | report | Fingerprints the extracted references — duration, hash, band profile — and prints their pairwise separability. That separability is the ceiling any detector can reach on this cue set. |
| `tools/cue/detect.py WINDOW...` | report | Template-matches the references against captured windows and reports per-sample score, onset, and level above background. Matches each reference's transient core by default (`--core`); whole-sample matching measured 19x fewer detections of the positive control on device. `--scan` reports onsets across a long recording, `--subtract` removes the per-run background profile. Fail-closed: empty, silent, clipped, or too-short windows are `UNKNOWN`. |
| `tools/cue/evaluate.py BACKGROUND` | report | Injects a reference into a real captured window at swept signal-to-background ratios and reports class-level hits and margins, with and without per-run background subtraction. A controlled lower bound, not a held-out detector result. `--anchor <dB>` is the gate-1 mode: it treats that level as a real thud detection's measured level and tests each vocal at its own played level relative to it, deriving the offset from the source channel volumes and reporting how much louder it would need to be. |
| `tools/cue/scan-night.sh WAV [--refs DIR]` | report | Scans one night's captured audio for Balloon Boy's vent bang, denoising before the cascade because that is measured to matter: injecting 52 copies of sample 17 into 159.5 s of real night background and scanning, the raw capture confirms **3/52** and the denoised one **27/52**, all 27 true and none false. Its floor is about **-12 dB** relative to background (0 dB -> 27/52, -6 -> 17/52, -12 -> 7/52, -18 -> 0/52), so a zero means "no bang above that level", not "no bang". `grade-run.sh` calls it whenever a run kept audio, and says so plainly when none was kept. |
| `tools/cue/label-misses.py VISUAL AUDIO --start-ns N` | report | Scores the bang detector's miss rate against visually labeled arrivals. The label is the lit opening going bright->dark, so it is independent of the detector under test; the luma split is derived from the recording and a dwell filter rejects screen flicker, which otherwise reports a confident rate from noise. Prints a rule-of-three upper bound and refuses to be believed below 60 events. |
| `tools/cue/export-model.py --refs DIR --cue C=H[,H] --threshold C=S --margin M --calibration NAME --output OUT` | generator | Turns uncommitted reference WAVs into an externally consumed `cue-model-v1` text file: each reference's most energetic 0.40 s core is resampled to 4 kHz and base64'd with its cue name and threshold. The APK deliberately ships no game audio or matcher; pass the result to `tools/cue/audio-authority.py --model` after calibrating it for the actual BlueALSA/ESP32 transport. Output remains a derived cue template, restricted to ignored `captures/cue-helper/models/` or outside the repository, and refuses overwrite. |
| `tools/cue/correlate.py` | report | Full-rate waveform correlation: the confirming stage of the cue detector, and **the control that refuted the 22 thuds**. A band-feature detector reported 22 thuds across 285 s of night audio and was believed until this disagreed on all 22. Run by hand against a chosen pair; it grades no run. |
| `tools/cue/test-cue.py` | check | Asserts the cue front end on synthesised signals only — level invariance, onset accuracy, fail-closed screening, and that background subtraction raises a transient. Runs in `tools/test.mjs --engine`. |
| `tools/cue/build-shadow-windows.py TRACE LABELS --output OUT` | module | Joins a raw `cue-shadow-trace-v1` file (the ARM/RESULT lines the archived legacy runner's `CUE_SHADOW` recorded beside the anchored PCM) to independent JSONL truth labels and emits `cue-shadow-window-v1` JSONL for `evaluate-shadow.py`. Detector output never supplies its own truth. |
| `tools/cue/evaluate-shadow.py WINDOWS --max-error CUE=RATE... --output OUT` | report | Evaluates `cue-shadow-window-v1` rows with whole-session holdouts (a session lives in exactly one split). Says `PASS` only when the caller supplies simulator-derived max-error bounds, the untouched holdout observes zero errors, and the rule-of-three upper bounds fit them. Output is a durable `cue-holdout-v1` report (the APK model provisioner that once verified it was retired with the Companion's audio path on 2026-09-27). |
| `tools/cue/test-build-shadow-windows.py` | check | Asserts the trace→window join: header and hash validation, label independence, and that an unlabelled window is dropped rather than guessed. Needs no device. Runs in `tools/test.mjs --engine`. |
| `tools/cue/test-evaluate-shadow.py` | check | Asserts the holdout evaluator: session-split exclusivity, the zero-error + rule-of-three `PASS` condition, and that a shared calibration/holdout session is refused. Needs no device. Runs in `tools/test.mjs --engine`. |
| `tools/cue/test-export-model.py` | check | Asserts `export-model.py`'s model text: core selection, resample, base64 round-trip, the ignored-path and no-overwrite refusals, and the `evidence=shadow` default. Needs no game audio. Runs in `tools/test.mjs --engine`. |
| `tools/cue/test-latency-experiment.py` | check | Phone-free regression for the experiment's monotonic-clock interpolation, visual bright->dark labeling, and session manifest shape. |
