# Device tools

Everything that runs a night on the phone, observes it, or grades what it
recorded. The labels (**check**, **report**, **device action**) are defined in
[`../README.md`](../README.md); anything marked **device action** sends input to
the connected Android device, so confirm the device, focus, screen state and
selected night before running it. Captures and extracted game content are local
evidence, not repo assets.

## Coordinates, state, and active trials

Nights run through `tools/device/night-run.sh`, which drives `npm run
device:campaign`; `npm run device:campaign` without `--live` is the phone-free
dry run. The legacy shell route was archived on 2026-09-25
(`docs/ARCHIVED-ROUTES.md`).

| `tools/device/phase-reconstruct.mjs --run DIR [--night N] [--seeds N] [--out FILE]` | report | States the phase a device run actually delivered, from that run's own bundle. Recovers the opening prefix length from the first gate (whose accumulated lag is zero by construction), then separates the planned `#phase-offset`, the uncompensated arm-release lag, and the per-cycle gate lag, and reports the delivered offset per cycle. The interval between the game's true first night frame and the classifier calling it is reported as `UNKNOWN` with its bracket, because nothing in a bundle measures it. `--night` adds the minus-toys model's win/mask-tick response over one game second of phase (`--seeds`, default 100 -- a band either loses every seed or wins nearly all of them), the contiguous loss bands, and the rate when the phase is drawn uniformly instead of held (`--runs`, default the golden 3000). Those stamps and a seed read from `logcat -v epoch` are different clocks; on night6-c2-01 they stood 1374.8 ms apart, and comparing them unconverted placed a press reconstruction 1.37 s late. Without an anchor the block is `null`, never a guess. Exports `reconstruct`, `lossBands`, `phoneWallFrom`, `SCHEMA`. No device. |

## Recorded-trial analysis

**Start here.** `night-run.sh` drives one device attempt and calls `grade-run.sh`
from its exit trap, so the pipeline runs without anyone remembering to invoke it.
`grade-run.sh` runs every instrument below against one run -- the video
instruments, and, when the run left a campaign bundle, the executor-owned ones
(`run-report.mjs`, `phase-reconstruct.mjs`) -- and prints one verdict; the
individual entries are for when you need one of them alone. Quote the interval it reports, never wall clock -- nights 6-36 and 6-37
were published at 163 s and 153 s and graded at 26.0 s and 72.2 s.
