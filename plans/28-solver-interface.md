# The solver interface: one MCP surface over four games

**Status: proposed 2026-09-20, Pedro's directive.** Written in answer to the
question "at maturity, what does someone — or someone's agent — call, instead
of investigating the game by hand?"

**Steps 1–4 built 2026-09-29** and served by the `fnaf-solver` MCP server
([surface](../docs/device/COMPANION-MCP.md)): `claim-envelope-v1` in the kernel,
emitted by `evidence -- show|promotions --envelope` and `review -- query promotions
--envelope`; `describe`; the five resources; the four refusals. **Step 5 built
2026-09-30:** one `truth` tool (op `decode | events | object`) over the caller's
own local dump, in `packages/source` (`src/truth/` reads, `decompile/truth.mjs`
finds the dump and decodes); the three `jobs.*` aliases folded into one `jobs`
tool, eleven tools in all. Step 6 (`sim.*`, `device.*`) remains. Which of the
four gaps still hold is `npm run review -- describe fnaf2`, not prose.

Plan 25 horizon 3 designs a loop that runs *this* lab. This plan designs the
surface a *stranger's* lab calls. They are different problems: the self-running
loop may trust its own memory, and an outside caller may not.

Nothing here is a claim or a Plan 12 rung. Every number below was measured on
the date it carries and says how. Where a thing is not measured it says
`UNKNOWN` and what would close it.

## What this is not

It is not a rewrite, and it is not an agent. It is a **read-mostly projection**
of registers this repository already generates —
[contracts](../docs/architecture/generated/contract-register.json),
[commands](../docs/architecture/generated/command-registry.json),
[the chronicle](../packages/review/src/chronicle-schema.js),
[the evidence graph](../docs/evidence/graph.json) — plus two write paths that
already exist behind gates ([simulation](../packages/propose/bin/plans/bundle.mjs),
[device](../apps/desktop/src/device-cli.js)). What is new below is envelope, routing and
refusal; the knowledge is already here and the safety boundary is already proven
in [`companion-mcp.mjs`](../apps/desktop/src/companion-mcp.mjs).
`UNKNOWN(not-estimated)`: no line count or schedule is offered, because none was
measured and an invented one would be the tautology mistake 7 describes.

## The gate: this does not start yet

**Restated 2026-09-25** ([`ROADMAP.md`](ROADMAP.md), step S6): the trigger is
S1's first promotion edge in `docs/evidence/graph.json`, not all of custody and
not Plans 26 and 27 finishing. The reason below stands: the interface's headline
field is provenance, and it cannot ship while that field is empty on every win.

The standing directive (Pedro, 2026-09-06, retargeted 2026-09-17) is Night 7
reliability and the promotion of what is already won. Plan 26 is gated on the
same custody debt and Plan 27's rebrand is sequenced after it. **This plan sits
behind all three**, for a reason specific to it: an interface whose whole value
proposition is "every answer carries its provenance" cannot ship while its
headline provenance field is empty on every winning run.

Building it first would not merely be premature — it would encode the custody
gap into a public contract.

## Who the interface is for

The finder does not want a bot that clears FNaF 2. They want to **stop
investigating**. The hours they would otherwise spend go to four things:

1. decoding the game,
2. knowing which mechanic claims are load-bearing,
3. knowing what has already been refuted,
4. touching a phone without breaking it or lying about the result.

An interface that exposes only "run the winning route" saves the fourth and
leaves the first three to be redone. The product is not the route. It is the
**chain plus its epistemics**: decoded events -> semantic model -> timed
schedule -> graded physical outcome, where every link states what it is worth.

## The load-bearing decision: a typed claim envelope

Every tool returns one shape. The vocabulary is not invented here; it is
[`docs/README.md`](../docs/README.md)'s evidence labels and
[`chronicle-schema.mjs`](../packages/review/src/chronicle-schema.js)'s statuses, verbatim.

```json
{
  "claim":        { "...": "the answer" },
  "label":        "SOURCED | CALIBRATED | DEVICE_MEASURED | INFERRED | MODEL | UNKNOWN",
  "target":       "com.scottgames.fnaf2@2.0.7+26 · runtime 770.0 build 296",
  "cite":         ["fnaf://truth/fnaf2/frame/12/group/677", "commit:e14ce7b"],
  "status":       "standing | superseded | retracted",
  "supersededBy": null,
  "notMeasured":  ["mask window at AI 20 vs Balloon Boy — model and phone disagree"],
  "reproducer":   "npm run evidence -- why night6-n6h2-01-20260920T024030Z"
}
```

Three fields carry the weight.

**`label`** is what makes the project worth depending on rather than merely
reading. A caller cannot distinguish a measured number from a plausible one
unless the interface says so in-band, on every response.

**`notMeasured`** is the anti-confabulation lever. An agent fills gaps by
guessing *because nothing told it where the gap was*. Naming the edge of
knowledge on every answer is worth more than any single answer. The thirteen
mistake-register entries are thirteen instances of a competent reader treating
an unmeasured quantity as measured.

**`status`** makes negatives first-class. A refuted mechanism is today
discoverable only by reading the right handoff; it must come back attached to
the query that would otherwise re-derive it.

`target` is a package name because Plan 26 measured that **the package name is
the only thing that identifies the game**: all four report plausible-looking
but differing `versionName`s on an identical runtime.

## The surface

Six namespaces, eleven tools. Agents degrade past roughly fifteen, so a tool
earns its slot or is folded into a parameter.

### Entry point

`fnaf.describe({ game })` — the coverage map. Per mechanic: its best label,
whether the phone has confirmed it, which disagreements are open, what is
`UNKNOWN` and what would close it. **This is the tool that prevents hand
investigation**, because it answers "what can you actually tell me?" before the
caller starts probing. It exists nowhere today.

### Truth — the game's own event sheet, queryable

- `truth.decode({ apk | package })` — pull, determine the per-build handle
  scramble `K` by object-type agreement, cache. The estimator reproduces
  FNaF 1's `K=0` and FNaF 2's `K=28` exactly at 1.0000 agreement with a ~0.39
  margin over the runner-up (Plan 26).
- `truth.events({ game, query })` — "what sets `hallLit` false?" returns the
  group, its conditions and its actions. Not prose.
- `truth.object({ game, name | handle })` — type, frames, created-by,
  destroyed-by.

This is the highest-value layer and the least accessible one:
[`packages/source/decompile/`](../packages/source/decompile/) is scripts plus a directory on one machine. It is
also what makes "answer from the dump, not the model" enforceable instead of a
habit a tired reader drops.

### Understanding — the model, and where it is wrong

- `model.explain({ game, mechanic })` — the implemented rule, the dump lines it
  was translated from, its label, and its known divergences from the phone.
- `model.disagreements({ game })` — the open model-versus-phone register,
  ranked. A caller should be made to read this first; today it is prose spread
  across session handoffs.

### Decision — the cheap oracle

- `sim.night({ game, night | dials, route, seeds })` — enforces the 3000-seed
  floor **in the tool**, refuses below it, and offers exhaustive-over-65,536
  because the 16-bit LCG is a property of build 296, not of FNaF 2. Returns
  killer shares and death-time quantiles, never a bare win rate.
- `sim.search({ game, night, family, budget })` — every negative names the
  family it searched, as Plan 16's recorded negatives do. "Unwinnable" is always
  family-scoped.
- `sim.margin({ plan })` — the slack audit: every timing floor, its measurement,
  its margin. Refuses under 33 ms.

### Embodiment — the existing boundary, widened but not loosened

- `device.capabilities({ serial })`, `device.plan({ winner })` -> hashed bundle,
  `device.run({ bundle, mode })` -> lease, deadline, retained telemetry, held in
  a queue when the phone is absent, `device.grade({ run })` -> cycle ledger,
  death cause, phase reconstruction.
- No taps, no coordinates, no shell. `companion-mcp.mjs`'s refusal to expose an
  actuator is the right instinct at the right layer and survives unchanged; see
  [device safety](../docs/operations/DEVICE-SAFETY.md).

### Proof — and the one thing a caller may not do

- `proof.evidence({ run | query })` — list, show, diff, replay, why.
- `proof.promote({ run })` — **proposes** an edge and returns a structured
  refusal until a human approves it.
- `proof.custody({ pack })` — fetch and hash-verify blobs through
  [the vault](../packages/review/src/vault.mjs). Without it a third party receives claims they
  cannot check, which is the state the project is in today.

## Resources and prompts

MCP's other two primitives fit this repository unusually well and are entirely
unused by the current server.

**Resources** give stable, citable URIs: `fnaf://chronicle`,
`fnaf://evidence/graph`, `fnaf://contracts`, `fnaf://refuted`,
`fnaf://game/{pkg}/controls`. A caller that cites `fnaf://truth/fnaf4/group/738`
in its own write-up produces a conclusion someone else can audit — which is the
difference between an answer and evidence.

**Prompts** ship the rituals rather than hoping they are read: the migration
sequence (characterize -> contract test -> change -> compare semantic traces ->
switch -> remove shim), the session opener (name the rung and the physical
artifact), and "run `capabilities` before proposing an instrument".

## The refusals are the product

Thirteen mistake-register entries are thirteen ways a competent agent reaches a
confident wrong answer. Prose has not stopped the fourteenth. The interface must
**refuse the known-bad move, with a citation and a remedy**:

```json
{ "refused": true, "rule": "seam-slack",
  "because": "plan clears MONITOR_MASK_READY_MS by 0 ms; a floor must stand 33 ms above its own measurement",
  "cite": "CLAUDE.md#mistake-7", "remedy": "maskOffMs 9260 -> 9560" }
```

| Refusal | Enforces | Already a gate? |
|---|---|---|
| Win rate quoted under 3000 seeds | the census standard | partly — Plan 05's admission gate still says 1200 |
| Timing floor cleared by < 33 ms | mistake 7 | yes, `test-seam-slack.mjs` |
| "Systematic miss" below five positive reads | mistake 12 | yes, `run-report.mjs` |
| A directional constant reused in reverse | mistake 10 | no |
| An instrument proposed before `capabilities` | mistake 8 | no |
| `UNKNOWN` consumed as a number | the charter | no |
| A promotion requested by a caller of the interface | Plan 12 | yes, `promote` refuses without an attestation bound to the pack; since 2026-09-27 the project's own agents may write one, only through `evidence -- attest` |

Those refusals are the accumulated cost of every wasted night, and they are the
part that genuinely transfers to a stranger. Four of the seven do not exist yet.

## What exists, and the four gaps

Already built, and more than most projects ever have: the contract register, the
command registry, the chronicle corpus with kinds/labels/rungs/statuses,
[`evidence.js`](../apps/desktop/src/evidence.js) with real claim ceilings and a `why` verb,
the content-addressed vault, a proven MCP safety boundary, capability preflight,
and the per-game vocabulary registry added to
[`vocabulary.js`](../packages/source/src/clockwork/vocabulary.ts) this week.

Missing:

1. **The envelope is not shared.** Every tool prints its own shape, so a caller
   cannot tell a measured number from a guess without reading the tool's source.
2. **Truth has no programmatic surface.** The highest-value layer is the least
   accessible one.
3. **No coverage map.** Nothing answers "what do you know about FNaF 3?" in one
   call, so a caller has no way to stop investigating except by exhausting the
   documentation.
4. **Custody is incomplete and promotion is empty.** 7 of 148 runs are
   `DEVICE_MEASURED`; zero are promoted. At maturity this is the difference
   between an interface someone can rely on and one that merely asserts.

## Two boundaries that would void the whole thing

**Publishing the corpus.** Dumps, recordings and game frames may not ship. The
consequence is architectural and clarifying: **the server ships the decoder, not
the decoded data.** The caller points it at their own copy of the game and it
reconstructs ground truth locally in minutes. That boundary is also, by luck,
what makes one server work for all four titles — and it is the same rule Plan 17
and Plan 25 horizon 2 already operate under.

**Letting a caller promote.** The moment `proof.promote` succeeds without a
human, every label in every envelope becomes worthless — and the labels are the
product. Generators propose edges; humans approve support, refutation,
supersession and retraction, as
[the evidence policy](../docs/evidence/README.md) states. On 2026-09-27 Pedro
delegated the Plan 12 attestation to the project's own agents, through
`npm run evidence -- attest`, which re-derives every other check from the pack.
That delegation is his to this repository's agents, not to the interface's
callers: `proof.promote` still only proposes.

## Sequence

Each step is useful alone and none requires the next.

1. **The envelope, as a core contract.** A `claim-envelope-v1` beside the other
   61, with a validator. Retrofit `evidence.js` and `sim` output first — they
   already carry most fields under other names. *Milestone:* two existing tools
   emit it and a contract test pins the shape. *Done 2026-09-29.*
2. **`fnaf.describe`, built from the registers that already exist.** No new
   measurement; it is a join over the chronicle, the contract register and the
   evidence list. *Milestone:* it reports FNaF 2 honestly, including the four
   gaps above, without a human editing its text. *Done 2026-09-29.*
3. **Resources before tools.** The five URIs are read-only projections and need
   no safety review. *Milestone:* a cold agent answers "what has been refuted
   about Foxy?" by citation, in one call. *Done 2026-09-29.*
4. **The four missing refusals.** Cheapest real safety win in the list. *Done 2026-09-29.*
5. **`truth.*`.** The largest piece of new engineering, and the one that makes
   the other three games cheap. *Done 2026-09-30,* as one MCP tool `truth` and
   `npm run review -- truth`: `events` returns the groups that read or write an
   object, an alterable value, a flag or a global, as frame, `g###` and parsed
   condition and action fields; `object` returns type, frames, created-by and
   destroyed-by; `decode` runs the local CTFAK dumper on a caller's APK or CCN
   and estimates `K` by object-type agreement (built here: nothing in the
   decompile chain estimated it). Answers are `SOURCED` and cite
   `fnaf://truth/<game>/frame/<n>/group/<g>`, readable back as a resource. The
   dump is found through the untracked `packages/source/decompile/local-vault.json`
   or `$SIXAM_TRUTH_VAULT`; with none, `truth` refuses naming the decode and
   `describe` reports gap 2 closed with `no local dump configured on this host`.
   Checked on a synthetic dump only (`packages/source/test/truth.test.js`); on
   this host the estimator reproduced the table above from the four local
   copies, FNaF 1 `K=0`, FNaF 2 `K=28`, FNaF 3 and 4 `K=29`, each at 1.0000,
   and nothing it read was committed. Open: where each object is *placed*
   (frame instances carry a second, layout scramble, 48 on FNaF 2, that is not
   estimated per build: `UNKNOWN`); `K` is still an estimate, not a read of
   `COI.loadHeader`; the older rendered per-frame sheets are refused, not read;
   and only the handful of engine ACE numbers that decide read or write are
   named.
6. **`sim.*` and `device.*`,** which are wrappers over existing gated paths.

`UNKNOWN(not-designed)`: transport, authentication and whether the server is
distributed at all. Nothing above assumes a public deployment; a local stdio
server for one caller is the only mode measured here.

## What this plan does not do

It does not rename anything — Plan 27 owns that, and the server name
`fnaf2-cue-helper` moves with the scope, in that plan's commit, not this one. It
does not promote a run, add a rung, or authorize a device session. It does not
supersede Plan 25 horizon 3: a self-running lab and an interface for outsiders
share registers but not requirements, and if only one is ever built it should be
horizon 3, because this plan has no value until there is something promoted to
serve.
